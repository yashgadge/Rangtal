# Rangtal Storage Architecture

## 1. Path Structure
The Firebase Storage bucket is strictly partitioned into distinct namespaces to enforce ownership, isolation, and lifecycle policies.

### Participant Private Files (ID Cards, Photos, Receipts)
`participants/{uid}/verification/{fileId}`
- **Owner**: The participant (`uid`).
- **Access**: Participant (read/write own), Admin (read), Volunteer (read ONLY IF explicitly granted `VIEW_PARTICIPANT_DETAILS`).
- **Limits**: Max 5 MB per file.
- **Allowed Types**: `image/jpeg`, `image/png`, `application/pdf`.

### Registration Documents
`registrations/{registrationId}/documents/{fileId}`
- **Owner**: The creator of the registration.
- **Access**: Creator (read/write), Admin (read).
- **Limits**: Max 5 MB per file, `image/jpeg`, `image/png`, `application/pdf`.

### Event Assets (Public)
`event-assets/public/{fileId}`
- **Owner**: System / Admin.
- **Access**: Public (read), Admin (write).
- **Limits**: Max 10 MB per file, images only.

### Exports (Private)
`exports/{exportId}/{fileName}`
- **Owner**: Admin who requested the export.
- **Access**: Requesting Admin ONLY (read). System (write).
- **Limits**: Generated by Cloud Functions only. Client upload strictly banned.

## 2. File Restrictions

### Validation
- **MIME Type Validation**: Enforced via `request.resource.contentType.matches()`. No `application/octet-stream` or `text/html`.
- **Size Validation**: Enforced via `request.resource.size`. Usually 5MB (5 * 1024 * 1024 bytes) for user uploads.

## 3. Upload & Deletion Policy
- **Upload**: Participants can upload to their own `/participants/{uid}/...` folder. The UID in the path MUST exactly match the authenticated `request.auth.uid`. Path traversal is blocked.
- **Overwrite/Replacement**: Participants can overwrite files in their own directory. This allows them to fix a rejected ID card (status `REQUIRES_CORRECTION`).
- **Deletion**: Pure deletion by participants is denied to prevent "missing reference" errors where Firestore expects a document that was deleted. Users can only overwrite (replace) existing files.

## 4. Download Security
- Sensitive files are NOT public. There is no `allow read: if true` on participant directories.
- Download tokens (generated by Firebase Client SDKs) are unguessable, but we still enforce strict Rule-based access for `getDownloadURL()` to ensure only authorized actors can even fetch the token.
- Web clients fetching images must attach the Firebase Auth token for the rules to allow the read.
